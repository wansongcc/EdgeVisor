## 修复与容量策略

- 默认上下文改为 4096，仍受模型原生窗口上限约束。显式 `--max-seq-len 0` 使用原生窗口；拒绝负数、非数字和溢出值。
- 2048、4096、8192 是方便选容量的档位，不是硬性要求。根据内存预算向下选择，不做盲目翻倍分配；设备可能被系统 OOM 直接终止。该模型 4096 的完整 KV 约 896 MiB，40960 约 8.75 GiB，尚未计入权重、临时缓冲与冗余层。
- README 删除 F32 激活缓冲宣称及模型下载引导，要求自备兼容模型/tokenizer；纠正大小、后端构建选择、steps 含义、28 层的 14/14 双机比例和恢复条件。F32 激活缓冲失败按要求不修复；F32 KV 缓存是另一种内存用途。
- 预留设备加入前完整读取并校验 KABT/KVAK，防止 ACK 混入性能/采样帧。新连接继承非阻塞设置，有限次数的读/窥探使用非阻塞接收，避免收到性能帧后等待下一帧而停顿。
- 内部调度等待预留加入提交，然后按真实流水线顺序与当前层归属选择邻接阶段；提交前验证接收端已有权重和源端归属。
- 根节点等待尾端结果时检查下一跳离线，处理成功发送后仍留在内核缓冲的激活；缓存就绪时接管并重新发送，否则会话重启。影子 KV 每 token 仅执行一次，防止重复运行污染历史。

缓存接管对照统一使用温度 0、seed 42、512 上下文、96 steps、各阶段单线程，以及覆盖故障阶段的两层冗余。环境变量为 `DLLAMA_BUBBLE_SHADOW_KV=1`、`DLLAMA_BUBBLE_SHADOW_KV_ASYNC=0`、`DLLAMA_TOKEN_TIMING_PRINT=1`；CLI 使用 `--runtime-redundant-boundary-layers 2 --nthreads 1`。根接管拓扑为 nx1→nx2→nano2、比例 `1@24*1@2*1@2`；中间设备接管拓扑为 nx1→nx2→nano2→nano1、比例 `1@22*1@2*1@2*1@2`。

每种拓扑先完成无故障基线，再在实时日志中观察到 pos≥24 后停止指定 worker，比较全部 `(position, token)` 对。重复测试先清空旧日志，并对 root/worker 使用行缓冲，防止旧日志或缓冲输出触发错误注入时机。

## 限制

ROG 复测时另一个 Python 进程占用约 1120 MiB 显存，GPU 利用率 100%、温度 87°C；没有终止该进程。相同模型/默认上下文在单线程下通过。README 已补充 `--nthreads 1` 用法与竞争负载说明；未证明外部进程是全部超时的唯一原因。

本轮只验证 0.6B Q40，不构成 14B、所有 Q40 模型或满 4096 token 持续生成的保证。拓扑与后端变化可能改变 token；加入测试验证通信和持续生成，未宣称与单机逐 token 一致。只有缓存接管使用同拓扑的有/无故障基线并通过逐 token 比较。缓存不足和尾端故障仍使用会话重启，重启后的 token 可能变化。
