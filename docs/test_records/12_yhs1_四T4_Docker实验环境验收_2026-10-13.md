## 网络实测

用 C++ TCP 探针传送并逐字节校验 4 MiB，发送方等接收完成 ACK；不是只测成功写入发送缓冲。整形施加在 node0 的容器 `eth0`，node1 为接收端。

| 场景 | 接收端实测 Mbit/s | 结果 |
| --- | ---: | --- |
| 无整形 | 8224.134 | 通过 |
| TBF 5 Mbit/s | 4.818 | 通过 |
| netem 20 Mbit/s + 50 ms | 17.961 | 通过 |
| 撤销整形 | 10524.163 | 通过 |

5 Mbit/s 用例接受 3.5–6.5 Mbit/s、20 Mbit/s 用例接受 12–24 Mbit/s；无整形/撤销整形要求高于 100 Mbit/s。保存了 qdisc 配置及计数。短流包含 TCP 启动、探针 CPU 校验和网络开销，不能把无整形结果当作物理网卡带宽。


## 模型实测

统一使用 CUDA、`--nthreads 1 --max-seq-len 512 --temperature 0 --seed 42`；普通长 prompt 为 `List 20 detailed facts about Paris. Number each fact.`。静态四阶段 PP 为 `--ratios '1@7*1@7*1@7*1@7'`，三个 workers 在端口 19393 监听。长 prompt 共 20 tokens，`--steps 64` 限制总 position，因此生成 44 tokens；它不是额外生成 64 tokens。

| 场景 | 退出码 | 生成 tokens | 总耗时秒² | 日志 tokens/s³ | 会话重启 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 单卡短回答 | 0 | 3 | 6.033 | 27.12 | 0 |
| 单卡长回答 | 0 | 44 | 8.062 | 27.17 | 0 |
| 四卡静态 PP | 0 | 44 | 10.111 | 22.14 | 0 |
| 四卡尾端 5 Mbit/s | 0 | 44 | 64.917 | 1.12 | 0 |
| 四卡尾端 20 Mbit/s + 50 ms | 0 | 44 | 28.225 | 2.86 | 0 |
| 四卡撤销整形 | 0 | 44 | 10.302 | 21.79 | 0 |
| 四卡 `--auto` | 0 | 44 | 11.835 | 20.13 | 0 |
| 四卡中间 worker 掉线，96 steps | 0 | 76 | 16.451 | 24.74 | 1 |

² 包含本项 worker 启动、模型加载、推理和客户端观察开销，不是推理 kernel 耗时；不含 `finally` 收尾清理。³ 引擎输出的本次生成均值，不是多次重复实验的统计量。自动迁移/故障场景也不能与静态均值直接解释为加速或恢复开销。

- 短回答 `The capital of France is` 生成 `Paris.` 后遇 EOS，3 tokens 正常退出。
- 单卡与四卡静态基线的 44 个 `(position, token)` 一致；限速、延迟、撤销整形三项也全部与四卡静态基线一致。
- `--auto` 的迁移/控制链路能够完成：实际将 layers 1–6 从 node0 转给 node1，导出 264 行 KV（6 层、pos 0–43），收齐 ACK 后切换归属；还有反向 `1->0` 调整日志。root 收到 176 条 `[token-prof]`，无会话重启。root/worker 日志均未出现 `Bad PlanCommand`、`Invalid ACK`、`protocol error` 或 `terminate called`。
- **`--auto` 未通过输出一致性验收**：与静态基线首次不同在 pos=52，静态 token=7928，auto token=6864。差异发生在迁移之后；不能仅凭正常退出就判断 KV/数值结果正确，也不能尚未定位就归因于浮点误差。后续应固定迁移计划和输入前缀，对照 logits、迁移前后逐层 KV 与历史完整性，再判断原因。本轮运行器记录这项差异，不将它隐藏为完全通过。
- 故障用例在观察到 pos=33 后，只终止本轮记录 PID 的 node1 worker；root 发生一次 session restart，继续完成 76 个生成 tokens 并退出 0。没有配置热备 Shadow KV；该项证明重启恢复，不证明无重启热接管、严格输出一致或恢复延迟上界。采样观察含 SSH 延迟，不能将 pos=33 当作精确故障触发时刻。

完整运行退出 0。脚本检查四容器内无本轮 `dllama`/探针进程、19393/19400 无监听、`tbf`/`netem` 已移除。收尾时原有四个 vLLM PID 及约 6.7 GiB/卡显存占用仍在，实验推理显存已释放。四个容器保留为空闲状态，供后续 Coding 使用。

## 范围与限制

- 本轮是单次冒烟测试，不是置信区间、性能基准或论文正式结果；同机四 T4 不能代表四个物理移动设备的异构算力、无线链路与温控。
- `tc` 实测的是容器 `eth0` 的出站整形；限制尾端会同时影响它的采样与控制数据。模型加载也经过整形链路，总耗时不能直接解释为 steady-state 吞吐或迁移开销。
- 仅覆盖上述 3B Q40、512 上下文、28 层四阶段 PP；没有重测默认 4096 上下文、14B 模型、多线程、预留加入、Shadow KV 热接管或 root-coordinator 掉线。
- 后续可在这些容器内做可控限速、延迟、丢包与 worker 故障测试。GPU 频率控制属于物理 GPU 的全局状态，不能靠 Docker 隔离；共享服务器上不据此模拟独立设备 DVFS。
