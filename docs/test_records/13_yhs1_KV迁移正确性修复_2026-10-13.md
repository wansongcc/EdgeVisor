# yhs1：KV 迁移正确性修复回归（2026-10-13）

本记录是正确性验收，不是论文性能表。四个独立 Docker 各占一张空闲 Tesla T4，CUDA 75，单线程，Llama 3.2 3B Instruct Q40、Q80 同步、上下文 512、temperature=0、seed=42；四阶段各 7 层，steps=128，生成 108 token。

## 修复与发现

- 先前导出 KV 时，后续无关执行段会清空已取得的行。提交 bdb8add 将导出限定于启用的权威 attention 段，隔离候选缓冲并合并归属区间，避免失活影子覆盖。
- 本地 root 目标已安装 KV，却未计入完成批次；现在记录本地安装结果，参与完整性检查，不虚构网络 ACK 或传输字节。
- 二次 EXACT 迁移按初始静态边界选层；现在按当前权威归属选相邻边界，拒绝内部层、碎片范围和清空来源阶段。
- 尾端已有 profile/sample 帧排队时，原始 KV 导出响应会被错读。现在先解出并缓存完整数据帧，再有界读取导出头；部分帧、无响应和非法头测试同时覆盖 blocking/turbo。

## 保留的失败与边界

主机本轮工作区 `work/research_20261013/` 保留原始 root/worker 日志、命令、计划响应与构建失败记录：`diagnostic_baseline`、`diagnostic_kv_fixed`、`diagnostic_state_phase02`、`auto_phase02`、`auto_phase02c`、`diagnostic_tail_phase02c`、`build_state_phase02c`。服务端构建快照位于实验目录的 `builds/`，不覆盖失败快照。清理检查确认实验进程停止，tc 已复原。

旧版本移回 root 的“相同输出”实际是迁移失败后继续旧映射，不能算 round-trip。修复前长自动调度曾因尾端导出错帧 exit=1；本记录保留失败而不是删掉它。混合 TP、CPU/Vulkan/ARM、14B、完整事务版本 fencing、持续 API 会话与真实工具负载仍需后续专门验收。
