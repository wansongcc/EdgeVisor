# yhs1：连续会话与真实工具验收（2026-10-13–14）

结论：S1 的串行会话 token lineage、请求采样同步及一个真实工具诊断任务通过。没有证明并发多会话、大模型质量、异步准备或移动设备性能。

## 修复

- 移除按消息推算位置的 NaiveCache。每次编码完整 canonical prompt，只有显式 `edgevisor_session_id` 相同且已消费 token 历史是严格前缀时才复用；改历史、换会话、匿名请求都明确开始新 lineage。
- pref​​ill 不采样、不产生尾端 token 帧；decode 从 prompt 最后一个 token 开始，修复旧的越界/错误下标路径。
- 最后采出的输出作为 pending input 单独报告，不计入已写 KV。新 lineage 清掉 root/worker 的影子 frontier、旧采样缓存和未提交状态。
- 每个请求同步 temperature、top_p、seed 和递增 generation；所有活跃 worker 在应用参数和 history reset 后 ACK。运行时 context key、lineage、generation、缓存量和 pending token 可核对。
- 非法 JSON、参数、小数/超大整数 max_tokens、容量超限在写流头和改 KV 前返回 400。计量失败不能留下可继续的有效 ledger。

## 实测

同记录 13/14：四个 Docker 各占独立空闲 T4，3B Q40、CUDA、单线程、上下文 512。API 特意设置 prefill batch=1，覆盖每个 pref​​ill 都可能误发采样帧的路径。

| 场景 | 单 GPU | 四阶段 root 采样 | 四阶段尾端采样 |
|---|---|---|---|
| canonical warm / cold 第二轮答案一致 | 通过 | 通过 | 通过 |
| 换会话、改前缀、匿名请求不复用旧 KV | 通过 | 通过 | 通过 |
| 10 种非法请求返回 400，原有效 ledger 不变 | 通过 | 通过 | 通过 |
| 每请求重置 temperature/top_p/seed，随机采样可重复 | 通过 | 通过 | 通过 |
| SSE 与非流式答案及 lineage metadata 一致 | 通过 | 通过 | 通过 |
| 实际 calculator → 自主 final_answer | 通过 | 通过 | 通过 |

API 共 60 个检查请求（每种配置 20 个，其中 10 个成功 generation、10 个拒绝）。算术续写第一轮 KV frontier=41，第二轮复用恰好 41 行；warm 与完整 cold 均得到 126。真实工具任务中，模型首先生成 calculator 调用，执行 `(17+25)*3` 得到 126，然后自行生成 final_answer；各配置 2 次模型生成、1 次实际工具调用、0 次格式修复、0 次强制动作/答案。工具前后复用 163 个已消费 token，context/lineage 相同。

CLI 的静态、root/尾端往返和自动迁移再回归：108 token 均与未计量静态一致；往返各 2 次真实提交，自动 2 次 6 层提交，frontier=50/70，无 session restart。CPU 和 CUDA CLI/API 全新构建及 10 个模型无关 C++ 测试通过，Python 25 项证据/自治/二进制来源测试通过。

这轮是正确性诊断，各配置只有一个独立任务。部分 CLI 测试与隔离 CPU 构建重叠，不把其耗时用于论文性能比较。没有从少量 generation 推断 p99、能耗或任务成功率。

## 保留失败，避免虚假的 quality 结论

移除隐藏的强制参数、partial-JSON 修复和自动答案后，初版工具协议曾在单卡上失败两次：模型执行了 calculator，却重复调用并输出多个 JSON，不能判为 task_success。目录 `gate_agent_phase04d`（tool 观察角色）、`gate_agent_phase04e`（user 观察角色）完整保留失败。随后只补全通用协议说明“工具结果由观察提供，结果足够时输出 final_answer”，不提供标准答案、不给固定下一动作、不改模型参数，最终诊断才通过。这是开发期协议调试，不是三个样本的统计质量结果。

`runtime_loop` 默认 autonomous，严格读取单个完整 JSON，真实执行工具。没有 objective checker 则 quality=null。历史强制消融显式标为 scripted，其完成结果为 scripted_workflow_completed，不能计入自治质量。真实工具客户端区间和 root 区间各自在自己的时钟内核对，不能跨进程相减。
